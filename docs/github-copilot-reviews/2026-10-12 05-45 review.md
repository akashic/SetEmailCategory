### [P1] Verify the complete Exchange management-scope filter

`/home/runner/work/SetEmailCategory/SetEmailCategory/scripts/Grant-MailboxAccess.ps1:94-95`

When a management scope with the expected name already exists, the script only checks whether its filter contains the mailbox address. A broader or inverted filter such as `PrimarySmtpAddress -ne 'target@contoso.com'` passes this check, after which the script can assign `Mail.ReadWrite` to that scope and grant access beyond the single mailbox the setup is intended to protect. Validate that the existing filter is semantically identical to the expected single-mailbox filter before creating the role assignment; also verify any existing assignment has the expected role, service principal, and scope. There are no tests covering this safety check.

### [P2] Use a token endpoint in the OAuth access-code definition

`/home/runner/work/SetEmailCategory/SetEmailCategory/connector/apiDefinition.swagger.json:103-105`

The Swagger 2.0 `accessCode` security definition sets `tokenUrl` to the same `/authorize` endpoint as `authorizationUrl`. OAuth clients use `tokenUrl` to exchange the authorization code for tokens, so clients that consume this security definition will send that exchange to the wrong endpoint and fail to authenticate. Configure the appropriate Microsoft identity token endpoint and keep it consistent with the connector OAuth settings.
