# Journal — 2026-10-22

## Session — 10:02

**Summary:** This continues the [09:30 session](2026-10-22%2009-30%20journal.md), which added the NSG rule and existing-subnet support. It covers a detailed review of that change, fixes for everything the review found, an assessment and fixes for four CodeQL findings, a list of open networking questions, and the commit and pull request.

**Discussion & decisions:**
- **Review.** The review covered the Bicep, both scripts, the workflow and the parameter file. Two platform facts were checked on Microsoft Learn rather than taken from memory:
  - A VNet can't be linked to two private DNS zones with the same name.
  - App Service VNet integration needs `virtualNetworks/read` as well as `subnets/join/action`.

  It found 16 issues. The serious ones were:
  - Re-using an app subnet while the template creates its own DNS zones would either fail to link, or take over storage name resolution for every other workload in that VNet.
  - With central DNS, nothing registered the private endpoints, so the app couldn't resolve storage.
  - Network Contributor on a whole platform VNet was too much to give an identity GitHub can use. That grant came from the earlier session's own choice to widen subnet scope to the VNet.
- **Fix choices.** The user asked for all the possible fixes, plus the `-ParameterFile` option for `Setup-GitHubOidc.ps1`.
  - **Re-used app subnet:** now requires `createPrivateDnsZones = false`. Hub zones can be named with `existingBlobPrivateDnsZoneId` and `existingTablePrivateDnsZoneId`, and `vnetDnsServers` points a template-created VNet at the hub resolver.
  - **Roles:** the earlier answer was "Network Contributor on the subnet"; the user's "all fixes" overrode it. The script now creates a join-only custom role, *SetEmailCategory Network Join*, and grants it on each subnet and NSG. It adds Reader on the VNet, because the Learn page above says VNet integration needs to read it, and Private DNS Zone Contributor on hub zones, the least-privilege role Learn names for writing DNS records. `-UseBuiltInNetworkRole` grants Network Contributor instead where custom roles aren't allowed.
  - **One source of settings:** `Setup-GitHubOidc.ps1` now reads the network settings from the parameter file. The separate `-Existing*` arguments were removed rather than kept alongside, so the script and the deployment can't drift apart.
- **CodeQL.** The four findings were judged as follows:
  - The null dereference was a false positive (the `1` arm only runs when `page` isn't null). It was rewritten as a list pattern anyway, which clears the alert without a suppression.
  - The undisposed `HttpClient` in tests was real but harmless (a fake handler holds no sockets). Fixed because the fix is cheap.
  - "Use Select" was cosmetic; applied as a one-line change.
  - "Use Where" should be dismissed as Won't fix: its filter reads the list being appended to, so the explicit loop is clearer.
- **Branch, not `main`.** The changes went to a new branch because a push to `main` touching `infra/` or `src/` runs the production deploy workflow, and the setup guide expects changes to `main` to come through PRs.
- **Journal naming.** The user asked for journal file names to include the time (`YYYY-MM-DD HH-mm journal.md`, like the earlier 2026-10-12 entry), so this entry is its own file rather than appended to the 09:30 one.
