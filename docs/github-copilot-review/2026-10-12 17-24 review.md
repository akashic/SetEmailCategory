## Findings

### [P2] Reject undefined numeric category modes

[`RequestValidator.cs:41`](/home/runner/work/SetEmailCategory/SetEmailCategory/src/SetEmailCategory/Models/RequestValidator.cs#L41) defaults a missing mode but does not verify that a supplied enum value is defined. `JsonStringEnumConverter` accepts integer values by default, so a request with `"mode": 99` can pass validation. `MailCategoryService.Merge` has no matching case for that value and returns the existing categories, leading to a misleading success response. Validate that the mode is a defined `CategoryMode` before processing.

### [P2] Match the token scope to the configured Graph cloud

[`GraphAuthHandler.cs:9`](/home/runner/work/SetEmailCategory/SetEmailCategory/src/SetEmailCategory/Graph/GraphAuthHandler.cs#L9) always requests a token for `https://graph.microsoft.com/.default`, while [`Options.cs:14-17`](/home/runner/work/SetEmailCategory/SetEmailCategory/src/SetEmailCategory/Options.cs#L14) allows `GraphBaseUrl` to be changed for national clouds. Changing only the base URL would send a token for the wrong resource. Derive or configure the token scope consistently with the selected Graph cloud.

### [P2] Bound request-body size before deserialization

[`SetCategoryFunction.cs:60-64`](/home/runner/work/SetEmailCategory/SetEmailCategory/src/SetEmailCategory/Functions/SetCategoryFunction.cs#L60) deserializes the request body before validating identifier and category limits. An authorized caller can submit an oversized JSON body and cause excessive memory use. Enforce a request-body size limit before or during deserialization.

### [P2] Account for aggregate Graph concurrency across instances

[`GraphConcurrencyHandler.cs:13-21`](/home/runner/work/SetEmailCategory/SetEmailCategory/src/SetEmailCategory/Graph/GraphConcurrencyHandler.cs#L13) limits Graph requests per function instance, while [`functionApp.bicep:94-100`](/home/runner/work/SetEmailCategory/SetEmailCategory/infra/modules/functionApp.bicep#L94) permits scaling to many instances. The aggregate concurrency can therefore exceed the intended per-mailbox limit, reducing the limiter's effectiveness and increasing throttling and retries. Account for total app concurrency when setting the scale and throttling strategy.
